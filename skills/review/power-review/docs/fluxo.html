Como a skill trabalha

Pipeline linear com ramificações condicionais (MR vs local, Figma, escopo) e uma faixa paralela para Context Pack / Figma enquanto o worktree sobe.

início / fim decisão paralelo / subagente skip / no-op

Pipeline principal

ENTRY

Entrada do usuário

URL/IID de MR, “review desta branch”, ou pedido de re-review.

01

Resolver entrada + branches

glab mr view ou tip local. Guardar source, target, diff_refs (base/head/start). Nunca inventar base.

modes.md Comparing line
DECISAO

MR aberto?

Só então aplicar side-effects de início. Os dois caminhos convergem no escopo.

02 · SIM → START

Side-effects ao iniciar

apply_review_workflow.py start → stat:under review + reviewer @me + Jira Code Reviewing. Falha parcial: registrar e seguir.

só MR opened
02 · NÃO → SKIP

Sem side-effects

Modo local, ou MR merged/closed/locked.

convergem
03

Escopo do diff

resolve_review_scope.py lê o marcador <!-- power-review:head_sha=... --> e define full / incremental / noop.

04–07 · PARALELO

Contexto ∥ Worktree

Pack Jira/Figma e preparação do código podem avançar juntos.

lane A · contexto
04

Context Pack

Skill jira-figma-context (opcional), profile review. Sem a skill, pular o pack.

05?

Tem URL Figma?

Sim → subagente de fidelidade. Não → pular.

05

Subagente Figma × código

Só layout/tokens. Divergências viram achados.

∥ sync
lane B · código
06

Fetch + worktree

git worktree add -f /tmp/pr-* na source / tip.

07

Leitura completa

Arquivos do diff inteiros + detekt.yml (+ baseline).

08

Detekt (opcional)

./gradlew :<module>:detekt nos módulos tocados — evidência, não gate.

09

Prior comments (subagente)

Só MR. Classifica candidatos: NOVO | DUPLICADO | REFORÇO. Publica apenas NOVO + REFORÇO válidos.

prior-comments.md
10a · RESEARCH

Research no codebase (reuso)

Mapear funções, extensions, utils e padrões já existentes para validar DRY/reuso. Orquestrador faz inline (grep/leitura); pode delegar a subagente (Task/generalPurpose quando o escopo for grande — não é subagente fixo obrigatório.

inline (default) subagente opcional
10b · DOCS

Research de docs oficiais

Diante de dúvida técnica ou ao citar boa prática: buscar docs Android / Kotlin atuais (data do review via date) e linkar no achado. Feito inline pelo orquestrador — sem subagente dedicado.

inline developer.android.com kotlinlang.org
10–11

Analisar + ancorar

Persona + Detekt + aderência ao ticket + Figma + resultado do research. Cada achado: severidade, path, new_line, template Antes/Depois + Referência.

12

Preview + aprovação do usuário

Comparing line, aderência, Figma, modo, lista de achados, omitidos, status Detekt. Gate obrigatório antes de publicar.

human gate
DECISAO

Modo MR?

Define canal de entrega.

13 · MR

Publicar

post_review.py --input review.json — inline + nota com marcador.

13 · LOCAL

Entregar no chat

Review completo no chat. Sem publicação.

14 · FINISH

Side-effects ao finalizar

Se lista final tiver ≥1 CRÍTICO/ALTO/MÉDIO → requested_change. Caso contrário, no-op de label.

só após publish MR
15 · ALWAYS

Cleanup da worktree

git worktree remove --force /tmp/pr-* — independente do modo ou cancelamento.

Quem faz o quê — inline vs subagente

Trabalho Como Quando
Context Pack (Jira/Figma spec) skill jira-figma-context Se a skill existir (profile review)
Cruzamento Figma × código subagente Task/generalPurpose Só se houver URL Figma no pack
Prior comments (anti-dupe) subagente Task/generalPurpose Só mode MR
Research codebase / reuso inline default; subagente opcional Sempre na análise; delegar se escopo grande
Docs oficiais Android/Kotlin inline orquestrador Dúvida técnica ou citação de boa prática
Análise persona + Detekt + achados inline orquestrador Sempre
Escopo / workflow / publish scripts Python Conforme mode MR
i

Não existe um subagente nomeado/fixo só de “research de reuso”. A persona manda: “Research no código (delegar a subagente quando útil)” — mapear arquivos, padrões, código reutilizável, camadas e testes. O orquestrador também busca no repo para validar hipóteses (chamadores, cache, etc.).

jira-figma-context

Coleta Context Pack. power-review não reimplementa getJiraIssue / fetch Figma.

subagente Figma

Fidelidade layout/tokens. Condicional ao link no pack.

subagente prior

Anti-duplicação de discussions/notes. Só modo MR. Contrato em prior-comments.md.

research reuso

Inline ou subagente ad-hoc. Procura functions, extensions, utils e padrões para não sugerir duplicação.
